# HFS 阶段一基线性能数据

**记录日期**：2026-09-05  
**代码基线**：`main@431735e`（shard-35 收口）  
**测试环境**：Ubuntu VM，8 vCPU；FIO 3.42-139-gae35；MariaDB 10.11.14

本文件记录当前版本的第一阶段性能基线。数据用于后续实现和优化的回归比较，
不等同于生产硬件上的绝对性能承诺。

## 1. FIO 三路对比

### 1.1 测试口径

- 工作负载：`randrw`，读写比例 50/50。
- 块大小：4K、8K、16K、32K、64K。
- 测试范围：每个 case 256MiB。
- 运行时间：每个 case 15 秒。
- 线程模型：单线程。
- HFS/ext4：`psync`、`O_DIRECT`；HFS 使用当前 `libhfs.so` 和 Malloc bdev。
- SPDK：官方 `spdk_bdev` fio engine，`iodepth=32`，使用同规格 `Malloc0` bdev。
- 无 LD：不设置 `LD_PRELOAD`，直接访问 VM 的 ext4 普通文件。
- 三组均使用独立文件或独立进程私有 bdev；错误数均为 0。

说明：SPDK fio 插件本身通过 `LD_PRELOAD` 加载，但 I/O engine 是 `spdk_bdev`，不经过
HFS Hook。FIO 的无 LD 组使用 VM ext4 文件，SPDK/HFS 使用进程私有内存 bdev，三者不是
同一物理介质上的公平硬件对比；该结果主要反映文件系统层和 I/O 链路开销。

### 1.4 FIO 初步结论

- HFS 4K randrw 基线约为 12.97K 总 IOPS，当前版本错误数为 0。
- HFS 在本轮测试中高于 VM ext4 无 LD 组，但这是内存 bdev 与普通 ext4 文件的对比，
  不能解释为 HFS 普遍快于真实磁盘。
- HFS 相对裸 SPDK bdev 的差距主要来自文件系统元数据、fd/路径语义、同步 I/O 和 HFS
  请求调度层。
- 与 shard-31 同配置 Malloc FIO 结果相比，当前版本 4K randrw 读写 IOPS 下降约 5.4%，
  128K seq 读写 IOPS 下降约 1.7%，均低于阶段设定的 10% 回退门槛。

## 2. MariaDB 原生与 HFS Hook 对比

### 2.1 测试口径

- 服务端：MariaDB 10.11.14，使用 InnoDB。
- 两组使用相同服务端参数：`innodb-use-native-aio=0`、`innodb-flush-method=fsync`。
- 原生组：服务端未加载 `LD_PRELOAD`，数据目录位于 ext4。
- HFS 组：只有 MariaDB 服务端加载 HFS Hook，数据目录为 `/hfs/mysql`，后端为持久化
  SPDK Aio 镜像；客户端未加载 HFS。
- 数据集：每组新建独立数据目录和后端，创建 10,000 行测试表。
- `sysbench` 未安装，因此使用 `mysqlslap`：每个 case 2,000 次查询、3 次迭代。
- 读 workload：10,000 行范围聚合扫描。
- 写 workload：按连接 ID 分散到不同记录的单行 autocommit `UPDATE`。
- QPS 为 `2000 / mysqlslap 报告的平均秒数`，用于同机相对比较。

### 2.3 MySQL 初步结论

- 读路径接近原生：单线程基本持平，16 并发约下降 12.8%。
- 写路径差距明显：单线程和 4 并发约下降 66%，16 并发约下降 47%。
- 本轮写 workload 是每条语句自动提交的更新，包含较高频率的持久化路径；该结果不能
  直接等同于批量事务、异步提交或纯内存查询性能。
- 两组 12 个压测 case 均返回 0，测试表行数保持 10,000，未发现崩溃或表损坏。
- HFS 服务正常退出时日志出现一次 `ib_buffer_pool.incomplete` 创建失败，但 MariaDB
  仍输出 `Shutdown complete`；该问题记录在 `doc/bug.md` 的第 44 条，暂不把该退出
  阶段视为完全兼容。

## 3. 后续回归使用方式

后续性能回归至少应保持以下条件一致：VM vCPU、FIO/MariaDB 版本、块大小或 SQL workload、
运行时长、bdev 类型、文件/镜像容量以及是否启用 `O_DIRECT`。

FIO 三路结果不能跨物理介质直接比较；MySQL 原生/HFS 结果应分别报告读和写，不能用混合
平均值掩盖 fsync 写路径开销。
